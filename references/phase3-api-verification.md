# 阶段 3：API 验证

## 定位

回答两个问题：接口存在吗？鉴权拦到它了吗？越权、写入、注入验证不做（硬性规则 2）。

**整循环**：选候选（批上限见 SKILL.md「速率与预算总表」）→ 逐条请求并落盘 → 按判定表落结论 → 响应体挖掘（零请求）→ 待批准条目经用户点名回流候选 → 续批——至预算或护栏触线收工；挖掘回流来源仅在首批之后出现。

## 选候选

优先验证最可能免鉴权的候选（每批上限见 SKILL.md「速率与预算总表」）：

- 路径含 `public / anonymous / noLogin / open / guest / free`（作者命名即线索）
- 语言包产出的词（passwordlessLogin / export / permission 这类 i18n 高频接口名——见 phase2 §2 二跳补抓）
- **响应体挖掘回流的新条目**（来源=响应体提取，见「响应体挖掘」节；仅续批生效——首批候选时挖掘尚未发生）
- 页面启动时调用的（站点信息 / 菜单 / 主题 / 按域名查询）
- 空参数可响应的列表类

未选的留待办（硬性规则 3）。候选排序信号（仅对已有响应的条目有效——探测/下载/复用响应；纯 JS 提取条目按上表词频与启动期线索排）：响应带调试头（X-Debug/堆栈）> 报错信息冗长 > 401/403 资产（后续测绕过的高价值面）> 响应体小（薄应用，防护弱）> 非主流 Server 头（冷门栈，可能未打补丁）。

**探测响应复用**：探测已得响应的 PROBE 条目不重发——直接复用该探测响应作证据（任意状态码均适用），打开响应体按判定表落结论、状态记已验证，备注登记所复用探测响应的落盘文件名（跨会话核对与证据索引指向它）；需换方法或补头才另发（计入验证预算）。

**WSS/SSE 条目**：升级握手不在 GET/HEAD/OPTIONS 范围——不进入验证请求，保持未验证、备注标「WSS/SSE 通道，需专用客户端」；同路径普通 GET 的响应特征可作旁证记于备注。

## 速率参数（数值见 SKILL.md「速率与预算总表」；下列为总表未覆盖的执行细节与护栏细则）

- 成簇 403 / 超时：停。补 1 条已知正常请求判断"瞬时限速 vs 持久封禁"（诊断性重发属授权类别 ③，计入验证预算）；瞬时等窗口，持久记录后换目标。不尝试绕过。
- 每条请求的响应头 + 正文落盘（编号对应清单行）——结论的唯一依据，跨会话核对也用它。
- **跨会话窗口护栏**：核对手段 = 按落盘编号枚举、按 `.headers` 首行时间戳对单站点做窗口合计（编号做唯一键，落盘规则见 delivery §3），触线即窗口内收工（窗口长度与合计上限见 SKILL.md「速率与预算总表」）。
- **授权类别与记账额度是两个维度**：授权 ①②③ 看请求性质，速率表各行看防滥用记账——存活确认 GET 授权属 ①、记账计入白名单探测行，不是矛盾，各管各的。
- **下载无独立数量上限的原因**：下载集由已枚举的静态资源清单决定（有限集），实际约束是逐文件间隔；清单异常庞大时按站点分批拉取。

## 判定表

很多接口用 HTTP 200 包络业务错误（`{"code":-1,"message":"需要登录"}`）。**必须打开响应体看业务码**。结论取值以 delivery.md §0 词表为准：

| 响应特征 | 验证结果 | 备注 |
|---|---|---|
| 200 + 业务成功码 + 数据 | 未鉴权可读 | 单条无凭据请求即是证据 |
| 200 + 业务错误码 | 需凭据 | HTTP 层未被拦、业务层校验——**读 message 区分鉴权类与参数类错误**（参数缺失也落此格，备注写清）；应返回 401 却返回 200 可记为设计问题 |
| 3xx + `Location:` 头 | 不在此前缀 | 禁跟随重定向（env #8）下的原始形态；备注必填 Location 目标——尾斜杠类规范化目标可换 URL 再试一次，跨路径/跨域目标只记线索（第三方域/兄弟域不请求，硬性规则 6）；无 Location 的 3xx（304、异常 302）不落本行——备注记「3xx 无 Location」、验证结果留空、状态保持未验证 |
| 401 / 403 + 鉴权提示 | 需凭据 | 符合预期，正常态 |
| 404 + 框架错误体（小体积 JSON、回显 path） | 不在此前缀 | ≠接口不存在，换前缀可再试一次 |
| 404 + 大体积 HTML（Web 服务器默认页） | 不在此前缀 | 命中静态服务器，无额外信息 |
| 405 + `Allow:` 头 | 留空（按换方法后的响应另落对应行） | 存在但方法不符——在 GET/HEAD/OPTIONS 与 Allow 交集内换方法再请求（计入验证预算，口径见「速率与预算总表」），新响应按其特征另落对应行、该行备注要求随之适用；交集为空按词表例外：状态已验证、留空、备注必填「方法不符，Allow=…」 |
| 500 | 留空（词表例外；状态记已验证——delivery §0） | 请求已抵达后端并触发异常；保留请求样本，备注必填「500 已抵达后端触发异常」（后续注入/逻辑测试候选，本阶段不测） |

**网络层失败（超时、代理错误）不是判定结论**：条目状态改「未确认」、验证结果留空；不得写成「不在此前缀」，也不得写成不存在。

**catch-all 站的 200 不落 200 行**：该站任意路径 200 + HTML（基线判定见 phase2 §1.4）——两条 200 行均不适用，只能按 §1.4 的内容特征判；无特征条目保持未验证，备注标「catch-all 站，200 无判定意义」。

**未列出状态码的兜底**：有响应即证明接口存在；三值皆不适用按词表例外处理（delivery §0）。常见落位——400/422 = 参数不符（请求已到业务层，备注写参数问题）；429 = 限速非结论——「4xx 不重试」的唯一例外：等窗口后重试，与网络层重试合并计入同一上限（占预算，合并口径见 SKILL.md「速率与预算总表」），不重试则保持未验证、备注记限速；裸 403（无鉴权提示，WAF 拦截页常见）= 先对照同站其他条目排除「全站一律 403」（403 版 catch-all——全站拦截时存在性未证明，保持未验证、备注标「全站 403」），确属单点拦截才记存在被拦（验证结果留空、备注记拦截页特征）。

国际/REST 规范风格的示例（与上表同构落位，补齐示例生态）：`401 + {"error":"unauthorized"}`（OAuth2 风格）→ 需凭据；`404 + {"message":"Not Found"}`（Express/REST 风格小体积 JSON）→ 不在此前缀；`403 + {"detail":"..."}`（DRF 风格）→ 需凭据。用 HTTP 状态码规范返回的 API 与业务码包络型（200+code）API 都在表内，判定规则本体一致。

## 一发流（低成本高信息，按需选用）

时机：前缀试探在首批验证前做 1 次；差分对照与分页上限递增在得到「未鉴权可读」结论后做。

- **前缀试探**（属验证请求，授权类别 ③）：对 `/api/` 发 1 发。返回框架原生 404 且回显 `path` ⇒ 反代剥离了前缀，相对路径接口都能经本站访问，不用碰兄弟域/第三方域地址。
- **HEAD 判资源直链**：接口吐出文件直链时，1 条 HEAD 看 Content-Type / Content-Length / Accept-Ranges 即定论，不下载内容。
- **分页上限递增**（size=1/10/100/500）：实际返回数跟随请求 ⇒ 服务端无截断——量化"数据可批量拉取"程度的证据（计入验证预算）。
- **差分对照**：同一参数传"合理值"与"明显不存在的值"，响应逐字节一致 ⇒ 参数不影响取值（≠可枚举，不过度定级）；不一致 ⇒ 记录差异（计入验证预算）。
- **鉴权拦截判定**：对清单接口发 1 条无凭据 GET，落在 401（拦截器先生效）还是 200+方法不支持异常（请求已抵达业务层）——后者说明鉴权拦截器未覆盖该路径。结论只写到**备注列**的「鉴权拦截未覆盖」（不入验证结果词表列）。
- **CORS 带实测**：对关键接口带 `Origin:` 头发 1 发，只记录是否反射与 credentials 标志；根路径无 CORS 头 ≠ 全站无（逐接口判定才有效）。

## 响应体挖掘（递归发现）

```bash
python scripts/mine_responses.py --dir <站点>/verify --entry-list 入口清单.csv --csv mined-verify.csv
# 复用条目的证据在 <站点>/probe——对它再跑一遍，否则这批已验证条目不进挖掘循环
# 两遍分别落 --csv（如 mined-verify.csv / mined-probe.csv）再合并为一份待批准清单；--entry-list 传入口清单做去重基线
```

每条已验证接口的响应正文本身是接口发现数据源。验证一个接口后，打开响应体 grep 以下模式，命中的新路径回流入口清单（来源=响应体提取，**状态=待批准**）——挖掘产物**不自动进入验证**，须呈报用户、点名后方可转未验证并进入验证循环；点名验证后的响应再挖出下一层，同样待批准。

**挖掘模式**（对已落盘的 .body 文件执行，零额外请求）：

| 模式 | 匹配式 | 暴露什么 |
|---|---|---|
| 路径值 | `"/api/..."`, `"/v[0-9]/..."`, `"/[a-z]+/[a-z]+"` 在 JSON 值中 | 代码里没写死、由服务端下发的动态接口 |
| HATEOAS 链接 | `"links": {"next": "...", "related": "..."}` | REST 资源图的全貌 |
| 错误回显 | Spring Boot `"path": "/api/v2/..."` | 版本漂移——v2 存在但你只测了 v1 |
| URL 值字段 | `"upload_url": "/api/upload"`, `"callback": "/api/cb"` | 功能性端点 |
| 嵌套资源 URI | `"/api/users/123/orders"` 在数据字段中 | 你不知道的子资源 |

**去重**：新发现的路径须先与入口清单已有条目比对（含占位符归一化——`/users/123/orders` 与 `/users/{id}/orders` 同键），已有条目不重复入清单。

**风险列（呈报排序用）**：`mine_responses.py` 输出每条带「风险」列，路径命中危险词的标「⚠高危」并单独汇总——此「高危」= 危险词命中（脚本字面），与 leaks 级别=高的凭据定级是两套标准——呈报用户点名时按风险列排优先级（高危条目即使 GET 也可能触发副作用，点名前须人工确认）。

**预算控制（防递归爆炸）**：
- 响应体挖掘本身**零请求成本**（纯本地 grep）
- 但新条目的**验证**消耗阶段 3 预算（会话上限与口径见 SKILL.md「速率与预算总表」）
- 预算用完时：已点名未验证的条目留未验证（下会话继续）；未点名条目按本节开头的流转规则处置——状态不随预算变
- 递归深度上限（见 SKILL.md「速率与预算总表」，硬性；A 的响应发现 B，B 的响应发现 C，C 的响应发现 D——到 D 通常已无新发现，更深大概率在兜圈子）

## 红线（硬性规则 2 的阶段展开）

- 写方法（POST / PUT / DELETE / PATCH）一律不发——包括空 body 试探写接口是否免鉴权。确需测试写入，属后续独立任务，须用户逐次批准。
- 不上传文件、不提交表单、不触发验证码。
- 响应出现个人敏感信息（证件、手机号明文）：取证已达目的，停止扩大取样，立即报告。
- 结论措辞上限：「鉴权拦截未覆盖」（写备注列）、「数据未鉴权可读」（验证结果词表值）；「可未授权写入/修改」需要写方法验证，不在本阶段。

## 产出

更新入口清单（权威词表见 delivery.md §0）：已验证条目状态改「已验证」、验证结果填三值之一（例外按词表处理，delivery §0），备注写响应摘要（状态码/业务码/字节数）；网络层失败条目状态改「未确认」、验证结果留空，留待办。字节数与复测一致 ⇒ 稳定复现而非偶发，写进备注。
